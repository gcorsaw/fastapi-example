# Steps Completed
1. Create a new Project in Github and enter the required information and useful information (if applicable).
    ### Required information
    * Repository name
    * Configuration
        * Visibility (defaulted to Public, but can be made private)
    ### Helpful Information
    * Description of the project
    * README
    * .gitignore
        * As mentioned later on, a .gitignore or files that start with a period (.), are files that are going to be ignored. For more information refer to:
        [Ignoring files](https://docs.github.com/en/get-started/git-basics/ignoring-files)
        * If we desire a .gitignore, then we can specify which template we would like to use. In the case of the fastapi-example, we're using Python as our template.

1. Once the Project is created, with the code button, hit the down arrow and copy the HTTPS link to the clipboard.
1. Use the command line and clone the project to your workstation using `git clone <project-url>`. Verify that the project cloned successfully by using a ls command and compare the cloned contents to the GitHub directory listing. As a note: if a file starts with period(.) (i.e .gitignore), this is a special file that tells Git that this file and folder are to be ignored in a project.
1. The ls -a will show all of the files and it doesn't matter whether the files are apart of the .gitignore or not.
1. Once the files have been checked to ensure that they have been established, then perform a cat .gitignore command. This is to ensure that both the GitHub and the Ubuntu projects are properly formatted with the correct information.
1. To initialize the project, perform a `uv init .` command in the project directory, this command will initialize the project in your home directory. The `uv init .` command will also initialize the files that are within the .gitignore in Ubuntu and Github as well: .python-version, main.py, and pyproject.toml
    * However, the file names may change depending on which template that you're going to choose. In the case of the example, the template utilize Python.
1. To open VS code to add or test your files, use the `code .` command. This will open the files that are in your current directory. For example, in the fastapi-example, once the `code .` command is executed, it will open the .gitignore, .python-version, main.py, pyproject.toml, and the README.MD. To run a certain file (i.e main.py), use the `uv run <file-name>`. This will then run that specified file and print the result in Ubuntu. For this particular example, the command would look similar to `uv run main.py`. 
1. Once the file that you've selected is functioning properly without any errors, we can then check to see which branch we're currently in. For this we would need to use the `git branch` command. This will show the possible branches that are in our project. For this project, the branch that we're currently in is init-project. This is represented by the asterisk (*) and the current branch is going to be a different color of text (typically green).
    * There's also another branch in this project. The name for this branch is 'main' and this is not the branch that we're not currently in. However, we'll be changing to this branch later on.
1. After we check to see if our branches are present and running as they should be, we're going to check the status using the `git status` command and this command will delve into the branch that we're currently in. For example, in the fastapi-example project, this command will show the status of the current branch, that being the 'init-project' branch. Once the command is executed, this will show the files that are either yet to be added or files that are already added to the branch.
    * However, if the files are not yet added (typically in red colored font), then we need to perform a `git add file-name`. If there are more files to be added, then we would need to add those files to the list. The files separation **does not require** commas in-between each file name. For example (in the fastapi-example): git add .python-version main.py pyproject.toml uv.lock
1. To commit the project to GitHub, we would have to use the `git commit -m 'descriptive message'`, however, if we don't have an author identity known, then we will have to perform a `git config --global user.email "example@example.com"` (the double quotes are needed for the email) and we will have to perform a similar process with the user name as well. It follows a similar process, just with the exception of using the username that you desire. For instance `git config --global user.name "gcorsaw"`, in this case "gcorsaw" would be the user name that would be associated with the configuration.
1. After the author identity is created, then we can start to commit the project. As previously mentioned, we would need to utilize the `git commit -m 'descriptive message'`, the descriptive message would be what we would desire for the project description to be. In the case of the project, we would have the description be `'feat: initialize new python project'`. Once the command is executed, then the files that we wanted to add to the project will be changed so then we're able to view those files in GitHub.
1. When we perform a `git push`, if we get an error with **fatal: The current branch init-project has no upstream branch.**, this would then indicate that we haven't told the local Git installation about the remote Git repository our branch should be pushed to.
    1. For the command to be pushed to the branch, we will have to use the command of `git push --set-upstream origin <branch-name>`. In the case of the fastapi-example, the branch name would be init-project as we haven't changed to a different branch yet.
    1. After the command is executed, we would have to input the username and password for github. However, if the authentication fails (if HTTPS is being used), then we can transition to creating a SSH key.
        * The commands necessary to start this process is `ssh-keygen -t ed25519 -C "your_email@example.com"`. We would use the email associated with the GitHub account.
            * Once the command is executed, this will start the SSH key generation. In order to find our key, we'll use the `cat ~/.ssh/` commmand. This will show a list of the keys that are currently present, the key that we'll use will end in a `.pub`.
            * We will perform a `cat ~/.ssh/key-name.pub`, this will then print the output of the file (the key in this case).
    1. After we have the SSH key functioning, then we utilize the `git remote set-url origin git@github.com:owner/repository.git`, the owner value is going to be the username of the account, in this case it's going to be gcorsaw. For the repository, the value is going to be the repository(or project) that you're currently wanting to set the connection to.
        * As a special note, if we're doing the git remote set-url origin as an HTTP instead of SSH, then we would need to do `git remote add origin https://github.com/OWNER/REPOSITORY.git` instead of `git remote set-url origin git@github.com:owner/repository.git` command.
1. If we perfrom the `git push` command, we may get a 'fatal: The current branch init-project has no upstream branch' error. In order to not receive an error, we will have to use the `git push --set-upstream origin init-project`. This will then proceed through the list and if github.com hasn't been established yet in the list, then it will have to be connected and if we want to connect, we will have to say yes. Once that has been authenticated, then it add github.com to the list of known hosts.
    * After the process is completed above (Step 13), then it will enumerate the objects that we currently have (in the case of the example, it will be 7 objects) and it will proceed through the steps in order to proceed through the push process.
1. After the `git push --set-upstream origin init-project` command has finished executing, then we will perform the git branch command to see which branch we are currently in. As we are in the init-project branch, if we perform a `git pull` command, then it work through the branch to ensure that the configuration meets the specifications to merge with the reference of the 'ref/heads/init-project'.
    * For documentation purposes, the git-pull is going to fetch from and integrate with another repository or local branch. 
        * The `pull` command is a combination of `fetch` and `merge`.
        * The `merge` command is used to merge different people's work together with yours. The `clone` and `fetch` commands will download remote code from a repository's remote URL  to your local computer. 
1. If we want to switch to a different branch, then we will have to execute the command of `git switch 'branch-name'`. In the case of the example, `git swtich main` will be used to swtich from the 'init-project' branch to the 'main' branch.
    * Now if we do an ls in our current branch (main), we will see that we just have the README.md and the steps.md. However, if we do the same `git pull` command as before, then we will be able to get the same files that we do in the init-project branch. However, to ensure that we properly have the same files, we will have to perform the ls command.
